## 1. 这个工具解决什么问题

基地的耗电与自带发电之间总有一个**电量缺口**。如果直接用一块满速电池供能，发电量往往大于缺口，
多出来的电就被浪费掉。做法是让电池**间歇投入**：把输入电池按固定间隔分成若干份，只留一份送到热能池，
其余回流，于是电池被「拉长」投放，缺口刚好被补上。

关键就是算两件事：

1. **分流比取多少**——取太大补不满缺口，取太小又会浪费；
2. **怎么接出来**——游戏里只有 2 分器与 3 分器，如何用最少的器件拼出这个比例。

👉 直接在浏览器打开 **https://yhssyzgg-code.github.io/PWM_Power_Regulation_in_Endfield/** 即可试用。

## 2. 数学模型

### 2.1 符号

| 符号 | 含义 |
|---|---|
| $t$ | 基础电池间隔（秒） |
| $A$ | 单块电池发电速率（单位/秒），一块电池燃烧 $40$ 秒 |
| $Q$ | 负载消耗速率（单位/秒） |
| $d$ | 分流倍数，只能取 $2^{x_1}3^{x_2}$ |
| $d_i$ | 第 $i$ 条支路的分流倍数 |
| $C$ | 阈值，$C=\dfrac{40A}{tQ}$ |
| $f$ | 等效分流比（目标支路占输入的比例） |
| $E_{\max}$、$\mathrm{margin}$ | 后备电量容量与最低安全电量 |

### 2.2 单线：从能量守恒得到阈值

分流比相乘，整条链的减速倍数为

$$d=2^{x_1}3^{x_2},\qquad T=\frac{t}{f}=t\,d$$

一块电池在其燃烧期内提供 $40A$ 的电量，在一个输出周期 $T$ 内负载消耗 $TQ$，要求发电不少于消耗：

$$40A\ \geq\ TQ\ \Longrightarrow\ \frac{40A}{tQ}=C\ \geq\ d=2^{x_1}3^{x_2}$$

所以 $C$ 是分流倍数的**上限**：$d$ 越大，投放越慢，补的电越少。

### 2.3 多线：分流比相加

设 $n$ 条并联支路，第 $i$ 条输出周期 $T_i=t\,d_i$。多条支路并联时**到达率相加**：

$$r=\sum_{i=1}^{n}\frac{1}{T_i}=\frac{1}{t}\sum_{i=1}^{n}\frac{1}{d_i}$$

把 $n$ 条支路看成一个等效分流器，其分流比为 $f$，则送达率也可写成 $\frac{1}{t}\cdot\frac{1}{d_{\mathrm{eff}}}$。
与上式对齐即得

$$\frac{1}{f}=\sum_{i=1}^{n}\frac{1}{d_i}\ \Longrightarrow\ \frac{1}{f}\ \leq\ C=\frac{40A}{tQ}$$

**这就是统一判据**：单线是 $n=1$ 的特例，多线让 $\frac1f$ 可以取非整数，从而在数值上逼近阈值 $C$。

### 2.4 分数分流与单位分数分解

把 $\frac1f$ 写成最简分数 $\dfrac{k}{D}$，其中 $D=2^{a}3^{b}$，则要求能拆成若干单位分数之和：

$$\frac{1}{f}=\frac{k}{D}=\sum_{i}\frac{1}{d_i}\qquad\Longleftrightarrow\qquad \sum_{i}\frac{D}{d_i}=k$$

因为每个权重 $w_i=\dfrac{D}{d_i}=2^{\,a-x_{1i}}3^{\,b-x_{2i}}$ 本身仍是 2 与 3 的幂次之积，
而 $D$ 又是 $2^a3^b$ 的形式，所以 $k$ 与 $6$ 互质是必要条件——否则约分后 $D$ 会掉出 $2^a3^b$ 的形状，
分解就不再对应任何真实的 2/3 分流器组合。

> **关于公共分母的两套写法**
>
> 代码里用的是**最小公倍数**作为公共分母（记作 $D=\mathrm{lcm}(d_i)$）：此时每个 $d_i$ 都整除 $D$，
> 权重 $w_i=D/d_i$ 都是整数，且 $\sum w_i=k$（程序里已做校验）。
> 也可以改用所有 $d_i$ 的**乘积**作分母，得到的权重和记作 $k_n$；两者都能完成通分。
> 但硬性要求只有一条：**$D$ 必须保持 $2^a3^b$ 的形状，且 $k$ 与 6 互质**。
> 早前手稿把 $R_n$ 同时当作最小公倍数与乘积使用，是这里最容易出错的地方。

### 2.5 三条约束（搜索结果必须同时满足）

| 约束 | 含义 | 判据 |
|---|---|---|
| I 功率 | 一个周期内发出的电不少于消耗 | $\dfrac1f\le C$ |
| II 缓冲 | 稳态运行时后备电量不低于安全线 | 稳态最低电量 $\ge \mathrm{margin}$ |
| III 时序 | 相邻两块电池到达间隔不能短于燃烧时长 $40$ s，否则会排队 | 最小到达间隔 $>40$ s |

## 3. 网页功能说明

页面分左右两栏：左侧输入参数与搜索设置，右侧结果指标、电量曲线与分流树状图。

### 3.1 输入参数

| 控件 | 默认值 | 说明 |
|---|---|---|
| 基础电池间隔 $t$ | 2 s | 送入一块电池的间隔 |
| 负载消耗速率 $Q$ | 675 单位/秒 | 需要补的缺口 |
| 单块电池发电速率 $A$ | 3230 单位/秒 | 电池燃烧期的发电速率 |
| 后备电量容量 | 100000 | 协议储存箱容量 |
| 最低安全电量 | 500 | 稳态电量下限 |
| 搜索深度 | 标准 | 快速 / 标准 / 深入，决定搜索范围与耗时 |
| 最多子流数量 | 5 | 允许拆成几条支路 |
| 搜索时间预算 | 5 s | 超时即返回已找到的最优解 |

> 参数校验要求 $A>Q$；若 $A\le Q$，电池燃烧期间也补不满负载，模型不成立。

### 3.2 结果指标

计算完成后顶部给出六项指标：

- **等效比例 f**：以分数形式给出，如 `7/(2^6·3^1)`
- **有效减速倍率 D/k**：即 $\frac1f$，可与阈值 $C$ 直接比较
- **供电精度**：$\dfrac{\frac1f}{C}\times100\%$，越接近 100% 说明越贴近上限
- **稳态最低电量**：稳态段的最低后备电量，需不低于安全电量
- **最小电池到达间隔**：所有到达时刻中的最小间隔，需大于 40 s
- **热机结束时刻**：电量最后一次触底、系统进入稳态的时间

### 3.3 后备电量曲线

用矢量方式绘制的 $E\!-\!t$ 折线，含暖机段与稳态段：

- **绘制规则**：电池按到达时刻依次投入、每块烧 40 秒（不重叠、会排队）；
  燃烧期间净充电 $A-Q$，空闲期间净放电 $-Q$；电量被限制在 $[0,\ \text{容量}]$，
  触顶或触底时会插入折点。
- **参考线**：容量上限（红虚线）、安全电量（橙点线）、零点（灰虚线）。
- **公共周期**：绿色虚线每隔一个公共周期 $L$ 标一条，便于观察周期性。
- **热机结束**：紫色虚线，右侧为稳态段。
- **交互**：拖动平移、滚轮缩放时间轴、`Shift`+拖动框选放大、双击复位；
  手机端支持单指拖动与双指缩放；悬停显示该时刻的电量与所处阶段（热机／稳态）。
- **导出**：可把曲线导出为 CSV（`time_seconds,backup_energy`）。

### 3.4 分流器配合方案（树状图）

把等效比例还原成实际的 2/3 分流器接法。程序会**同时构造三种布局并取分流器总数最少的一种**：

| 策略 | 含义 |
|---|---|
| **公共因子共享** | 先串联各支路共有的 $2^{x_1}3^{x_2}$ 主干，再在末尾分叉出各自尾缀 |
| **2-在前 Trie** | 每条支路的「先 2 后 3」路径建 Trie，共享公共前缀 |
| **3-在前 Trie** | 同上，但路径顺序为「先 3 后 2」 |

图例：蓝色方块是 2 分器，绿色方块是 3 分器，橙色框是输出份额 $1/d_i$，
最左侧是输入。标题行会写明采用的策略与分流器总数。支持拖动、滚轮缩放、适应宽度与复位。

程序还给出**硬件复杂度估计**（各支路分流器指数之和），用于在精度相近的候选之间做取舍。

## 4. 实现要点

页面是纯前端实现，把原先的 Python 搜索流程移植到了浏览器端：

| 函数 | 作用 |
|---|---|
| `genPool` | 枚举 $D=2^a3^b$ 与附近的 $k$（要求 $k<D$、$2\nmid k$、$3\nmid k$、$\frac Dk\le C$），生成候选池 |
| `decompose` | 迭代加深 DFS，把 $k$ 拆成若干 $2^{x}3^{y}$ 权重之和，节点数超过 35000 或超时即中止 |
| `candidateSearch` | 逐个候选检查约束 II、III（`noPileup` 检查到达不排队、`energyAtEvents` 算稳态最低电量），按精度排序返回最优 |
| `simulateFull` | 生成完整时间轴的电量序列，自动判定热机结束点并抽稀到 40000 点以内 |
| `drawSplitterDiagram` | 三种布局择优，用 SVG 画出分流树 |

搜索强度由预算档位控制：

| 档位 | 指数上限 | $D$ 上限 | $k$ 窗口 | 候选上限 |
|---|---|---|---|---|
| 快速 | 8 | 5000 | ±2 | 600 |
| 标准 | 10 | 50000 | ±3 | 1200 |
| 深入 | 12 | 250000 | ±4 | 1800 |

**已知局限**：网页版是 Python 搜索流程的浏览器端近似实现，深度越高越慢；
另外模型对分流器的物理布局、输出时序做了理想化假设，与游戏实际表现可能有出入，
结果建议以游戏内实测校正（页面底部也保留了这条提示）。
