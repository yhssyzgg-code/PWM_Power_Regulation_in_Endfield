# 震荡供电分流计算器

这是一个单文件、无依赖的 GitHub Pages 网页，用来搜索《明日方舟：终末地》集成工业中的电池分流方案，并按 1 秒离散步长模拟后备电量。

在线使用：<https://yhssyzgg-code.github.io/PWM_Power_Regulation_in_Endfield/>

当前维护版保留了原仓库的分流搜索、公式代入、候选对照和 SVG 接线图，并补充了固定到达时序、满电暖机过程、排队、首块到达前缺供、周期复现、支路燃烧带和 CSV 导出说明。网页仍是模型工具，结果需要用游戏内实测校正。

## 1. 开始使用

直接打开仓库中的 `index.html` 即可。也可以在仓库目录运行：

```bash
python -m http.server 8000
```

然后访问 <http://localhost:8000>。不需要安装 Node、Python 依赖或第三方 CDN。

第一次使用建议点击“恢复默认”，再点击“计算分流方案”。默认参数是：`Q=325`、`A=1600`、`t=2`、容量 `100000`、安全电量 `500`、最多 `6` 条支路、深入搜索、满电起步。

## 2. 输入参数

| 参数 | 含义 |
| --- | --- |
| `Q` | 负载每秒消耗的电量。 |
| `A` | 一块电池燃烧时每秒发出的电量。当前模型燃烧 `40 s`。 |
| `t` | 上游电池供给间隔，按秒输入，可使用小数秒。 |
| 后备电量容量 | 储能上限；超过部分统计为溢出。 |
| 最低安全电量 | 周期运行希望保持的最低电量。 |
| 初始电量 | `满容量`、`0` 或 `半容量`。默认满容量，表示后备电量满、设备和传送带为空。 |
| 统一输送延迟 | 所有支路额外增加的延迟；没有延迟请填 `0`。 |
| 最多支路数 | 限制候选最多拆成多少条并联支路，范围 `1–8`。 |
| 搜索强度 | 快速、标准、深入。范围越大，耗时越长。 |
| 严格最简分数 | 控制当前 `D/k` 约分筛选；它是搜索实现选项，不是所有物理接法的普适定理。 |

网页会拒绝非正数输入，并要求 `A ≥ Q`。这是单燃烧槽模型的输入限制；`A < Q` 时，燃烧期间也无法抵消当秒负载。`A = Q` 表示燃烧时只抵消当秒负载、不增加后备电量。

时间轴左侧的 `T` 是同一支路的理论输出间隔。周期起点没有电池，支路第 `k` 块电池（`k=1,2,3…`）的固定计划到达按 `ceil(统一输送延迟 + k·T)` 取整到秒；因此首发时刻由实际时序决定，不再叠加额外的“暖机等待”。橙色区段显示电池实际进入燃烧槽的时间，若前面有电池占用燃烧槽，实际点火会晚于到达并显示排队等待。

固定到达时序默认折叠，展开后可设置统一输送延迟。无延迟时，T=324 的支路在 324、648、972、1296…秒到达；T=486 的支路在 486、972、1458…秒到达。972 秒的两块均计入 FIFO 队列；一块在 972 秒点火，另一块在 1012 秒点火（40 秒燃烧时长），后续到达不随排队顺延。

## 3. 计算模型

令燃烧时长 `τ=40 s`，单线分流倍数为 `d=2^x·3^y`，输出周期为 `T=t·d`。

- 单线阈值：`C = 40A/(tQ)`，要求 `d ≤ C`。
- 多线送达率：`f = Σ(1/dᵢ)`。
- 有效减速倍数：`d_eff = 1/f = D/k`。
- 平均功率必要条件：`d_eff ≤ C`。
- `D` 是支路分母的最小公倍数，`k = Σ(D/dᵢ)`。

网页每 `1 s` 结算一次，顺序为：

1. 结算本秒到达的电池；
2. 燃烧槽空闲时，取 FIFO 队首电池点火；
3. 燃烧中每秒净变化为 `A−Q`，空闲时每秒变化为 `−Q`；
4. 将电量限制在 `[0, 容量]`，并记录溢出和未满足负载。

首块电池到达前允许电量跌到 `0`，这不会单独淘汰方案；周期运行仍要检查安全线、末周期缺电、排队和状态复现。电量等于 `0` 与该秒发生多少缺供是两个不同指标。满电起步只是初始储能条件，不会改写任何电池到达时刻。

### 持续供电起点筛选上限

推荐方案、备选方案及单线对照均要求**已确认的持续供电起点 ≤ 2000 s**。等于 2000 秒允许通过，大于 2000 秒即淘汰，并记录实际起点和超限原因；尚未确认或仍会耗尽的方案不能进入通过列表。其他供电、安全电量和排队约束仍须全部满足。

该阈值比较的是持续供电最早起点，不是首次回满，也不是周期复现的验证完成时间。仿真仍可运行超过 2000 秒以确认后续行为。默认 324/486 秒示例的起点为 973 秒，验证完成于 2916 秒，因此不会被此阈值淘汰。

## 4. 结果怎么读

- **供电精度**：`(1/f)/C`，越接近 100% 越贴近平均功率边界。
- **首次点火**：第一块电池实际进入燃烧槽的秒数。
- **持续供电起点**：经完整周期复现确认后，从此秒边界开始，后备电量始终大于 0，不再耗尽。按 1 秒步长，取最后一次电量为 0 之后的第一个正电量边界；若从未触底，则为 0 秒。它不是首次回满，也不是完成周期验证的时刻。数值判断使用 `1e-8` 容差。
- **尚未确认 / 仍会耗尽**：未观测到完整周期复现时显示“尚未确认”；若复现周期内仍有电量触底，显示“仍会耗尽”，不给出虚假的持续供电起点。只有电量、燃烧剩余时间及包含支路身份和相对等待年龄的 FIFO 队列在周期边界复现，且完整重复周期电量始终为正、无缺供，才确认持续供电。
- **稳态最低 / 最高电量**：当前显示窗口最后一个公共周期的范围。
- **最长排队等待**：到达后等待 FIFO 燃烧槽的最长时间。
- **周期复现**：比较电量、燃烧剩余时间、队列状态和相对等待年龄；只看到电量回满不足以证明周期稳定。

默认示例会显示首块到达前段、首次点火附近、持续供电过程、最后两个公共周期和末周期等视图。曲线缩小时使用连续折线保留转折点，放大到足够比例后显示逐秒阶梯；底部支路导航条在持续供电起点前用低透明度淡玫红底色，起点及之后用蓝色；未确认起点或仍会耗尽时全段用淡玫红。底色不是逐秒缺供标记，起点之前也可能暂时有电；橙色仍表示实际燃烧时段，悬停可以查看到达和等待信息。

电量图支持鼠标 / 触控拖动、滚轮或按钮缩放、双击复位。分流器接线图支持拖动平移、滚轮缩放、放大、缩小、适应窗口和复位。

CSV 包含：

```text
time_seconds,backup_energy,burning,unmet_energy_this_second,phase
```

其中 `burning` 是燃烧槽状态，`unmet_energy_this_second` 是该秒未满足的负载，`phase` 区分首枚电池到达前、过渡段和周期窗口。

## 5. 接线图的边界

接线图用于说明 2 分器、3 分器、支路和端口相位的关系。它不证明回流网络、输送带带宽、端口占用、游戏内相位是否能精确实现，也不声称全局最少器件数或游戏实测最优。

分流方案搜索是有限枚举：有分母上限、支路数上限、公共周期上限和搜索时间预算。`gcd(k,6)=1` 一类条件只应理解为当前严格搜索的约束；关闭严格筛选可以探索更多候选。搜索没有找到方案，不等于数学上或游戏里不存在方案。

## 6. 维护与发布

仓库只有一个自包含的 `index.html`。修改后建议按顺序检查：

1. 恢复默认并完成一次计算；
2. 分别测试满电、空箱和半容量起步；
3. 检查首枚电池、持续供电起点、末周期最低电量和首块到达前缺供；
4. 拖动 / 缩放两张图，并调整浏览器窗口检查布局；
5. 导出 CSV，确认首行、末行和列含义正确；
6. 再提交到 GitHub，等待 GitHub Pages 部署完成。

本地维护时请保留 `index.html` 的历史快照。当前仓库中的 `index.online-before-maintenance.html` 是同步维护前的线上版本备份，`index.legacy-continuous.html` 是更早的连续事件版本。

## 7. 已知限制

- 未模拟线路损耗、实际设备启动延迟、回流拥塞和游戏内部未公开的结算差异。
- 各支路独立从自己的第一个完整周期开始到达，相位固定为 0；接线树的端口编号不再给到达时间增加偏移。实体接线仍需游戏内验证。
- 长公共周期可能超过仿真预算，会显示为尚未完成验证，而不是强行判定通过。
- 通过只表示在本页声明的单燃烧槽模型、当前输入和有限预算内通过，不是全局最优证明。

公式推导和历史修复记录保存在仓库相关文档中；若网页行为与游戏实测不符，应优先记录输入、版本、CSV 和复现步骤，再调整模型。
